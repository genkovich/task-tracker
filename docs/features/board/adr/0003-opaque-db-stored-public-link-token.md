# 0003 — Use an opaque DB-stored token for the public link

- **Status:** Accepted
- **Date:** 2026-08-20
- **Deciders:** genkovich (Architect + Security), during the `design` Socratic walk

## Context

AC-11 вимагає, щоб після відкликання public link жоден наступний перегляд ним більше не показував стан board. Spec §6.1 називає непередбачувану адресу лінка головним захистом і прямо вимагає security review — саме тому, що це новий неавтентифікований публічний доступ до даних команди. `docs/idea-brief.md` §10 називає це головним ризиком проєкту: «якщо лінк потрапляє в чат чи індекс пошуковика — борда команди стає видимою назавжди й будь-кому», якщо його не можна відкликати.

## Decision drivers

- AC-11 (cross-context): відкликаний лінк ніколи більше не показує стан, хай хто б за ним не звернувся.
- Spec §6.1 Security review — required.
- Spec §6.1 Abuse case: «Витік public link у чат чи індекс пошуковика: після відкликання лінк ніколи більше не показує стан board».

## Considered options

1. **Непередбачуваний токен, збережений у БД** — токен (128-біт random / UUIDv4) зберігається як рядок у таблиці Postgres поруч з board; API перевіряє токен пошуком у БД при кожному запиті viewer'а.
2. **Підписаний stateless токен (JWT-подібний)** — токен підписаний секретним ключем сервера, перевіряється криптографічно, без запиту в БД.

## Decision outcome

**Chosen:** Option 1 — непередбачуваний DB-stored токен. Відкликання (AC-11) — це один `UPDATE`/`DELETE` рядка, що виконується миттєво й без побічних ефектів. Stateless-підхід (Option 2) вимагав би або короткого TTL з примусовим переви­данням, або окремого «чорного списку» відкликаних токенів — тобто все одно потрібне сховище стану, просто складніше за просте видалення рядка; для однієї board це невиправдана складність.

## Consequences

**Positive**
- Відкликання й перевірка чинності лінка — проста, очевидна операція над одним рядком; жодної додаткової інфраструктури.
- Легко додати ротацію токена (видати новий, старий одразу недійсний) без зміни схеми.

**Negative**
- Кожен запит viewer'а — один похід у БД для перевірки токена (прийнятно при NFR ≥20 req/s на інстанс, spec §6).

**Neutral**
- Токен зберігається як звичайне поле в таблиці `boards`/`public_links` — деталі схеми належать стадії `data-model`, тут фіксується лише підхід (opaque + DB-backed), а не конкретні колонки.
